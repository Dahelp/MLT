# MLT: общая основа двух отдельных версий сайта

Основной сайт и мобильный сайт остаются отдельными реализациями по требованию заказчика. Общими являются данные, расчёты и поведение повторяющихся блоков. Их внешний вид может отличаться явно заданным вариантом компонента.

## Страницы и публикация

- Основная главная: `app/HomePage.tsx`; коллекции: `app/collections/[slug]/CollectionDetail.tsx`.
- Мобильная главная: `app/mobile-preview/MobileHomePreview.tsx`; коллекции: `MobileCollectionView.tsx` выбирает мобильный шаблон. Отдельный шаблон Freedom сохранён.
- `/{locale}/mobile-site/` — настоящая мобильная версия; `mobile-preview` — отдельные адреса предпросмотра. `previewMode` меняет переходы, но не цены и продукты.
- `public/.htaccess` направляет мобильные запросы главной и коллекций на мобильные HTML-документы. Сужение окна десктопного браузера не заменяет проверку этих маршрутов.
- Локали: `en`, `de`, `ru`, `it`, `pl`.
- `scripts/export-static.mjs` экспортирует обе версии. GitHub Actions при push в `main` собирает и публикует сайт на существующий Apache/PHP-хостинг. Worker/Vinext остаётся контуром сборки и локального запуска; PHP API не исполняется самим Vinext.

Все публичные страницы основного сайта, включая коммерческие и юридические страницы, используют один и тот же `main`-футер. Страница предложения показывает его вне печатного документа; при печати он скрыт. Перекрёстные ссылки юридической статьи и итоговая часть печатного предложения не являются отдельными футерами сайта.

`CollectionCarousel` — тонкий адаптер общей карусели для главных страниц. Он не содержит своей копии настроек Swiper. В коллекции создаётся одна видимая карусель; старые скрытые экземпляры удалены.

## Данные каталога и цены

Действующие активные записи PHP-каталога имеют приоритет над локальным резервом. Обе версии используют одинаковые правила сортировки, фильтрации продуктов и разбора тарифов, включая повреждённый JSON. Главные страницы также учитывают тарифы каталога.

Резервные цены сведены по ранее существовавшим серверным значениям `catalog.php`: Signature 10/14 дней — 4290/5890; Private 10/14/21 — 28429/39800/59700. Это устраняет старые расхождения локальных таблиц. Существующие записи базы данных не мигрируются и не перезаписываются этой правкой. В JSON отдельно сохранена ранее поддерживаемая оплата Private за 30 дней; она не добавляется в интерфейс выбора длительности.

Цены существующих заказов и расчёт платежей по сохранённому заказу остаются ответственностью серверной части. Не следует подменять их суммой из браузера. Рефакторинг не является аудитом безопасности платежей или миграцией бизнес-правил.

## Стили

Админка использует один постоянный каркас `app/admin/layout.tsx` → `app/OperationsShell.tsx`: меню, шапка, язык, уведомления, сворачивание и выход. Порядок пунктов, адреса и переводы определяются только в `content/operations-navigation.ts`. Все разделы передают в каркас содержимое через `OperationsShell`; внутри административного layout этот компонент выводит только содержимое и обновляет уведомления общей шапки. Не добавляйте отдельные меню, глобальные кнопки или копии шапки в страницы разделов. `useOperationsLocale` синхронизирует язык содержимого и каркаса. Условия MLT Flexible Protection находятся в «Платежи» → «Условия оплаты и возврата»; каталог содержит только объекты каталога.

Рабочий Apache-хостинг публикует статические HTML-файлы без сервера RSC. Переходы между разделами админки используют обычные ссылки: `next/link` запрашивает отсутствующие `.rsc`-адреса. Язык и сворачивание сохраняются в общем хранилище независимо от загрузки документа.

`operationsBootstrap.ts` применяет сохранённые язык и сворачивание в `<head>` до первого отображения. `OperationsText` содержит три варианта подписи в исходном HTML, CSS показывает сохранённый язык без ожидания React и без переписывания DOM. Содержимое раздела становится видимым после согласования клиентской локали; меню и шапка видны сразу. Не заменяйте ранний выбор языка только на `useEffect`: это возвращает вспышку EN → RU при каждом переходе. Общая подсветка SVG должна наследовать цвет пункта при active, hover и focus-visible; выделение не должно менять размеры текста.

Общие дизайн-переменные находятся в начале `app/globals.css`. Цвета обеих шапок используют `--mlt-nav-paper` и `--mlt-nav-ink`. Разные мобильные макеты сохраняют CSS Modules.

Удалены 400 деклараций, которые перекрывались более поздними декларациями того же свойства и селектора в тех же условиях `@media`. Порядок остальных правил сохранён. Правило скрытия старых каруселей удалено вместе с их разметкой. Это ограниченная очистка накопленного каскада: независимые стили кабинетов и коммерческих разделов сохраняются.

Новые изменения следует вносить в действующее правило компонента, а не добавлять очередное переопределение в конец файла. Одинаковое поведение не должно копироваться в мобильные шаблоны.

## Проверки

`pnpm test` собирает приложение и запускает HTML-проверки, проверки общего контента/расчётов и тесты мобильного viewport. Дополнительно PHP-файлы проверяются через `php -l`. UI следует проверять на основной и отдельной мобильной главной, коллекциях Freedom/Signature/Private, Smart Map и коммерческой странице.

Workflow публикации запускает `pnpm test` до экспорта и загрузки на хостинг. Непрошедшие проверки останавливают публикацию.

Полная проверка `tsc` в исходном проекте уже содержит ошибки кабинета/служебной панели, старые сгенерированные ссылки на fleet и недостающие типы Cloudflare. Эти ошибки нужно отличать от ошибок изменённых модулей; успешная сборка сама по себе не означает чистую проверку типов.

## Откат

До изменения создана метка `safety/architecture-before-20261018`, указывающая на исходный коммит `0ac41a9`. Ранее существовавшие незакоммиченные изменения не включаются в коммит рефакторинга; их локальная резервная копия находится в `.codex_tmp/before-architecture-user-changes.patch`.

Изменения этого рефакторинга оформляются отдельным коммитом. Для отката опубликованной версии используйте `git revert <коммит-рефакторинга>`, затем `git push origin main`. Это создаёт обратный коммит без удаления истории и запускает обычную публикацию. Не используйте `reset --hard` для отката рабочего каталога с чужими правками. Git-метка фиксирует исходное состояние исходников, а не резервную копию базы данных; изменений данных базы этот рефакторинг не выполняет.
