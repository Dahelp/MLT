# Локальные исправления зависимостей

## braces 3.0.3: GHSA-vfj7-8cjw-p6xm

23 октября 2026 года добавлен патч `patches/braces@3.0.3.patch` для переполнения стека на глубоко вложенных шаблонах. Официальная advisory: https://github.com/advisories/GHSA-vfj7-8cjw-p6xm.

Это собственное исправление проекта, а не официальный выпуск библиотеки. `pnpm audit` продолжает показывать advisory для версии 3.0.3; предупреждение не скрывается и не добавлено в исключения аудита.

### Как действует защита

- Парсер проверяет глубину при открытии фигурных скобок и круглых скобок. Смешанная и незакрытая вложенность также учитываются.
- Обходы compile, expand и stringify независимо проверяют глубину. Передача готового AST или прямой импорт внутреннего обработчика не обходит защиту.
- Фиксированный предел — 128 уровней AST, включая конечный узел; для обычного шаблона допускается до 127 вложенных групп. Превышение вызывает определённую `SyntaxError`, до исчерпания стека. Параметры вызова не позволяют отключить или поднять предел.
- Кавычки, экранированные скобки и символьные классы сохраняют обычную семантику; количество буквальных скобок само по себе не считается глубиной дерева.

Патч ограничивает конкретный сценарий переполнения стека при рекурсивном обходе. Он не объявляет библиотеку защищённой от любых возможных атак на CPU, память или комбинаторное расширение. Существующий rangeLimit сохраняется; ограничение глубины не заменяет ограничение общего объёма обработки недоверенных данных.

### Установка и проверка

Патч зарегистрирован для точной версии в `pnpm-workspace.yaml` → `patchedDependencies`; lock-файл фиксирует его хеш. Обычный `pnpm install --frozen-lockfile` применяет его автоматически. Не редактировать установленный `node_modules` вручную и не включать игнорирование ошибок применения патчей.

`pnpm test` запускает `tests/braces-security.test.mjs` до production-сборки. Тест проверяет обе реальные цепочки зависимостей: ESLint → fast-glob → micromatch → braces и Vinext → commonjs/dynamic-import → fast-glob → micromatch → braces. Обе должны использовать один исправленный экземпляр библиотеки.

Дополнительные проверки охватывают все публичные строковые методы, прямые внутренние обходы AST, циклический AST, границу глубины, обычные шаблоны сборки и отдельный процесс Node.js с размером стека 256 КБ. На исходном пакете вредоносный пример в таком процессе вызывает `RangeError: Maximum call stack size exceeded`; с патчем выдаётся ожидаемая SyntaxError, после чего обработка обычного шаблона продолжает работать.

### Когда появится официальное исправление

1. Проверить, что опубликованная версия исправляет именно эту advisory и защищает все используемые входы.
2. Обновить зависимость, адаптировать регрессионные проверки к официальному поведению ошибки и выполнить полный набор тестов.
3. Удалить локальный патч и его запись в patchedDependencies только после успешной проверки официальной версии. Не оставлять неиспользуемый патч с отключённой проверкой его применения.
