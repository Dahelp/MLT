Общий парк автодомов MLT

Модель KNAUS VAN I 650 MEG использует два физических юнита для Freedom / Freedom+, Signature / Signature Tailored и Concierge. Другие коллекции не включены в этот пул.

Интерфейс
Блок Select a motorhome находится непосредственно перед Your payment breakdown в основной и отдельной мобильной версиях. 16 фотографий идут в подтверждённом порядке из коллажей: внешний вид, планировка, интерьер, обеденная зона, передняя кровать, задние кровати, холодильник, кухня, душ, санузел, водяной отсек, туалетный отсек, гараж, газовый отсек, задний вид, заправочная горловина. Свайп, стрелки, точки; полноэкранная галерея поддерживает Escape, стрелки клавиатуры и возврат фокуса.

Резервирование
Новая заявка получает временный резерв на 30 минут. Брошенная неоплаченная заявка освобождает машину. Перед началом Stripe/PayPal checkout и перед списанием ваучера наличие проверяется повторно. Открытый checkout удерживает машину до подтверждённого закрытия провайдером, даже если время временного резерва вышло. Оплата, частичная оплата и подтверждённая оператором бронь удерживают юнит на весь срок поездки. Время checkout само по себе не освобождает автомобиль: иначе поздняя оплата могла бы создать овербукинг. Для зависшего checkout используется существующее закрытие оплаты в ЛК после проверки провайдера.

Все операции назначения берут блокировки строк юнитов в одном порядке, затем читают конфликты через FOR UPDATE. Даты — полуоткрытый интервал [подача, возврат): день возврата доступен для нового выезда. Один и тот же юнит должен быть свободен на весь период: наличие разных машин в разные дни не считается доступной поездкой.

Администрирование
Администратор: /admin/fleet/ («Парк автодомов»). Юниты создаются идемпотентной миграцией при первом обращении к PHP API. Ручные блокировки не могут пересекаться с действующей бронью/резервом этого юнита. Видны коллекция, номер заказа, даты, статус и назначенный юнит. Места подачи и возврата заполняются здесь; пока адреса не согласованы, ЛК показывает «Место будет подтверждено». Адреса не выдумываются из страны поездки.

Существующие подтверждённые/оплаченные брони этих коллекций без назначения блокируют весь пул на пересекающийся период. Администратор должен распределить их между Unit #1 и Unit #2. Пока остаётся неназначенная бронь, публичная доступность остаётся закрытой. Назначения с конфликтом одного физического юнита отклоняются.

Личный кабинет
В заказе хранится серверный снимок модели, фото, характеристик и назначение юнита. Публичный API доступности возвращает только ID модели и Available/Sold out по датам, без юнитов и заказов. Номер юнита возвращается владельцу заказа после оплаты; внутренние номерные знаки не используются. До оплаты модель отображается без номера юнита.

Публикация и проверка
Используется существующий workflow GitHub Actions. fleet-core.php, fleet.php и motorhomes.json загружаются на этапе зависимостей до обновления booking.php. Новая страница админки включена в статический экспорт. CI запускает tests/fleet-api.test.mjs на отдельной MariaDB; локальный запуск требует MLT_FLEET_TEST_DSN=mysql:host=127.0.0.1;port=<test-port> и при необходимости MLT_FLEET_TEST_USER / MLT_FLEET_TEST_PASSWORD. Тест создаёт только mlt_fleet_test. Он проверяет конкуренцию между коллекциями, защиту всего периода, обслуживание, истечение временного резерва, активный checkout, оплату, старые брони, приватность ЛК и адреса подачи/возврата.
