Telegram MLT: владелец, консьерж и продажи

Инструкция от 28.10.2026. Сейчас сайт использует один общий Telegram-чат. Заявка на автодом сохраняется в разделе продаж, но уведомление уходит в тот же чат, что и запросы консьержу. Роль сотрудника на сайте сама по себе не меняет получателя Telegram.

Подготовлено в коде: отдельный параметр telegram_sales_chat_id. После его настройки заявки с источником acquisitions и listing_ID_… идут в чат продаж. Поездки, консьерж и инвестиции сохраняют прежний маршрут. Пока новый ID не настроен, действует общий чат. Новая группа и передача прав ещё не выполнены.

1. Владелец создаёт группу продаж

  1. В своём Telegram создайте закрытую группу «MLT — Продажи». Создатель группы будет её владельцем.
  2. Добавьте только сотрудников, которые обрабатывают покупки, и существующего бота MLT Concierge. Уточните точное @имя бота у текущего администратора.
  3. Разрешите боту отправлять сообщения. Для обычной группы полные права администратора не нужны; доступ к удалению сообщений и добавлению администраторов не выдавайте без необходимости.
  4. Отправьте команду /start@имя_бота в группе. Отдельно откройте личный диалог с этим ботом и нажмите «Запустить / Start» — это нужно также для передачи самого бота.
  5. Передайте администратору сайта название группы и время команды. Не публикуйте токен бота в группе или скриншотах.

Альтернатива: можно направлять заявки прямо в личный диалог владельца с ботом. Тогда менеджеры не увидят их автоматически. Для совместной работы предпочтительна закрытая группа владельца.

2. Текущий администратор передаёт консьержа

Если это группа: добавьте владельца → откройте информацию группы → «Изменить / Управление группой» → «Администраторы» → выберите владельца, назначьте администратором → «Передать права владельца». Подтверждает текущий владелец со своего Telegram. Если кнопки нет, следуйте требованиям Telegram: двухэтапная проверка обычно должна быть включена более 7 дней, пароль не изменён последние 7 дней, вход на устройстве выполнен более 24 часов назад. Не удаляйте рабочую группу, ожидая разрешения передачи.

Если это личный диалог с ботом: перенести ваш личный чат в аккаунт владельца нельзя. Владелец запускает бота у себя, а администратор сайта меняет общий telegram_chat_id на ID личного диалога владельца либо его группы консьержа. История старого личного диалога автоматически не переносится.

Отдельно передайте самого бота: текущий владелец открывает официальный @BotFather → /mybots → выбирает нужного бота → Transfer Ownership / «Передать права» → указывает @имя владельца. Получатель должен предварительно написать боту. Это передаёт полный контроль над ботом, включая возможность удалить его; действие выполняют сами участники после проверки имени получателя. Владелец проверяет появление бота у себя в /mybots.

Передача группы, передача бота и изменение адреса уведомлений на сайте — три отдельных действия. Одно не выполняет остальные автоматически.

3. Администратор сайта подключает адреса

  1. На сервере получите ID нужных диалогов через официальный Bot API. Сначала проверьте getWebhookInfo. Если webhook пустой, найдите сообщение команды в getUpdates и возьмите message.chat.id (ID группы обычно отрицательный). Если webhook настроен — используйте уже работающий обработчик; не отключайте webhook ради определения ID.
  2. В защищённом серверном paypal-config.php сохраните существующие параметры и задайте ID. Этот файл не помещать в Git и не передавать через публичную страницу:
'telegram_chat_id' => 'ID_ГРУППЫ_КОНСЬЕРЖА_ВЛАДЕЛЬЦА',
 'telegram_sales_chat_id' => 'ID_ГРУППЫ_ПРОДАЖ_ВЛАДЕЛЬЦА',

Существующий telegram_bot_token должен принадлежать добавленному в обе группы боту. Альтернатива конфигурации — серверные переменные TELEGRAM_CHAT_ID и TELEGRAM_SALES_CHAT_ID; значения в PHP-конфигурации имеют приоритет. Сам файл .env.example на работу PHP не влияет. Если после передачи вы обновили токен, синхронно обновите его на сервере, иначе доставка остановится.

4. Вы и владелец проверяете результат

  1. Согласуйте с менеджерами одну заявку на автодом с пометкой «ТЕСТ маршрутизации — не обрабатывать». Дождитесь видимого подтверждения отправки.
  2. Убедитесь, что тот же номер заявки есть в админке и только в группе продаж.
  3. Отдельно согласуйте тест запроса поездки: он должен прийти в группу консьержа владельца, а не продаж.
  4. Владелец проверяет права управления группами и ботом. Затем пересмотрите состав участников и права бывших администраторов; не удаляйте доступ до успешной проверки.

До подключения нового ID уведомления продолжают поступать в прежний чат. Подключение и передача прав требуют действий владельца; инструкция сама настройки Telegram не меняет.

Официальные справочники: передача бота, получение обновлений и chat.id, условия передачи группы.
